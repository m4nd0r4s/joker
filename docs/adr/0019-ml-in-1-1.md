# ADR 0019 — ML in 1.1, with v1 prepared for it

**Status:** accepted (v1) · **Date:** 2026-09

## Context

v1 had ML (Burn, ORT, Hailo, streams, pipelines, training) in Phase 2. The central goal of Joker is to be the wildcard runtime that talks to devices. ML is fundamental, but it adds scope, pre-1.0 dependencies and specific hardware before the base is proven.

## Decision

ML leaves v1 and becomes **1.1**. With it go: M4 (streams), M5 (pipelines), M6 (scheduled writes), M7 (block signals), M10 (lineage), M16 for models, M17, M18 and M22. v1 **reserves** everything ML needs (document 11, §"Ready for ML"): the WIT interfaces `ml` and `frames` (returning `unavailable`), the `ml` resource class, the models section in the trace, the `.jkm` artifact type and the block and stream signal types.

## Reasons

- v1 becomes smaller and more focused, and can ship earlier.
- No v1 decision closes the door on ML: the reservations above make 1.1 a minor change.

## Consequences

- Stress rounds 2, 3 and 6 of document 08 describe 1.1 capabilities.
- Document 06 now has v1.1 scope.
- The Burn validation (document 06, §12.6) moves to the exit gate of 1.1.
