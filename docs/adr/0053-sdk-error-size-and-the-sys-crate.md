# ADR 0053 — The size of the SDK error, and the `joker-sdk-sys` crate

**Status:** accepted (v1) · **Date:** 2026-10

## Context

Writing `joker-sdk` (document 13, M0-SDK-MACROS) against ref/04 §4.1 and §4.7.1 showed two facts the reference does not state:

- Ref/04 §4.7.1 gives `Error` a `BoundedString<256>` message, inline because the cycle path does not allocate (§4.13). That makes `Error` 266 bytes. Every cycle task returns `Result<()>`, so every task, and every function of the app that propagates with `?`, moves a 266-byte `Err` variant; and Clippy's `result_large_err` (on by default, threshold 128 bytes) fires on every such function of every app, which an app built with `-D warnings` cannot ignore.
- The guest glue of the canonical ABI, generated by `wit-bindgen`, is `unsafe` code, and so are the `link_section` statics that hold the `joker:meta` fragments and the `critical-section` implementation of a component. AGENTS.md (invariant 10) allows `unsafe` only in `-sys` crates. The crate table of ref/04 §4.1 has no such crate.

## Decision

1. The `Error` of the SDK keeps its message inline, truncated to **112 bytes** at a character boundary, so `Error` is at most 128 bytes (121 today). The host still accepts and truncates `cycle-result.error.message` at 256 bytes, so tier 2 SDKs are unaffected.
2. The SDK has a fourth crate, **`joker-sdk-sys`**: the `wit-bindgen` bindings of `joker:runtime`, the `meta_fragment!` and `export_guest!` macros that `#[joker::app]` and `#[joker::cycle]` expand to, and the single-threaded `critical-section` implementation of Wasm components. Because the `unsafe` items come from expansions of this crate's macros, an app crate can `forbid(unsafe_code)`.

## Consequences

- Ref/04 §4.1 (crate table) and §4.7.1 change in the same commit.
- A longer explanation goes in the log (`joker::log`), not in the error.
